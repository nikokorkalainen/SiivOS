# Notes for Claude

SiivOS is a macOS optimizer app. Read `PLAN.md` first: it holds the approved plan, principles, and phase status. Update its status table when a phase changes state.

## Constraints

- Claude's cloud workspace is Linux. Run `./Scripts/check-engine-on-linux.sh` before committing engine changes: it installs Swift from download.swift.org (allowed in the owner's environment), compiles and tests `SiivOSCore`, and checks the app's syntax. Keep `SiivOSCore` compiling on Linux; put Mac-only calls behind `#if os(macOS)`.
- The SwiftUI app in `Sources/SiivOS` cannot be compiled here beyond that syntax check, so it is never type-checked before it is committed. Prefer well-established APIs and re-read new SwiftUI carefully. The owner builds on a Mac and reports errors.
- The owner's Mac runs macOS 15.8.3 with Xcode (installed 18 November 2026, version not yet confirmed). They have the repository cloned in Xcode on the branch `claude/intelligent-clarke-msqlh7` and get changes with Integrate, Pull. They build the real app with `bash Scripts/make-app.sh`, can run it from Xcode (scheme SiivOS, not SiivOS-Package), and can run `swift test`. All 178 engine tests passed on the Mac on 18 November 2026, including the ones that take real readings, run the protection check and gather a health observation. Sizes on disk are rounded up more on Linux than on a Mac, so a test that depends on a size limit must use files well clear of the limit; one that did not passed on Linux and failed on the Mac. An old ZIP copy of the project in the owner's Downloads folder has caused stale test results once; the current copy is the Xcode clone, whose Terminal prompt ends in `SiivOS %`. Ask for `swift test` output whenever the engine changes.
- Target macOS 14+, Swift tools 5.9 (Swift 5 language mode). Do not raise these without asking.
- The owner is new to Xcode and Terminal. Keep build and test instructions step by step, in plain language.

## Architecture rules

- `Sources/SiivOSCore/`: all logic that inspects or changes the system. No SwiftUI or AppKit UI code. Covered by tests.
- `Sources/SiivOS/`: SwiftUI interface only. It calls into SiivOSCore. Its look and wording follow `docs/design.md`. Colours are in `SiivOSTheme.swift`, section icons in `SiivOSIcons.swift`, and shared building blocks (panels, buttons, bars) in `Theme.swift`. `SiivOSTheme.swift`, `SiivOSIcons.swift`, `SiivOSWordmark.swift`, `SiivOSSidebarHeader.swift` and `GlintLoader.swift` come from the `claude/design-notes` branch, where the design work happens; run the syntax check after merging it, since that branch has shipped a file that did not compile.
- Every `Finding` a scanner returns carries a label, `safety` (Safe to remove or Check first), and a one-sentence `safetyReason`. A new scanner must decide both. Only items labelled Safe to remove count towards the Overview's "safe to remove" figure and are ticked by Tick All. A finding can carry a `displayName` for when its file name says little (`DerivedData` is shown as "Xcode build results").
- The Cleanup settings (`CleanupSettings`, kept in `cleanup-settings.json` by `CleanupSettingsStore`) are read by both the app and the agent door, so both scan the same way. A setting may only narrow what Cleanup lists; none may make it less careful. Folders the user leaves out are dropped at the engine level for every scanner, including items that have such a folder inside them.
- The Health Timeline (`Sources/SiivOSCore/Health/`) takes a reading when the app opens, at most every six hours, and keeps readings and changes in `health-history.json` next to the action log. Every point of the score comes from a named part with a plain-language reason (`HealthScoring`); keep the rules few, and never let the score scare: a firewall that is off and memory merely in use cost nothing.
- The menu bar icon and its panel are in `Sources/SiivOS/MenuBar.swift`; the Settings window, one tab for each kind of setting, is in `Sources/SiivOS/SettingsView.swift`. The window and the menu bar share `TimelineModel.shared` and `AppNavigation.shared`. With the menu bar icon on (the default), closing the window does not quit the app.
- The agent door (`Sources/SiivOSCore/Agent/AgentDoor.swift`, run by the `siivos-cli` tool in `Sources/SiivOSCLI/`) lets an AI agent the user already has ask SiivOS questions. It must stay read-only: it never calls `SafetyCore`, never writes a file, and answers nothing about the Mac unless the user has turned it on in Settings (`AgentDoorSwitch`, a file both programs read). A test checks that answering creates and removes nothing. `siivos-cli mcp` (`AgentDoorServer`) offers the same questions as MCP tools over the tool's own input and output, one JSON message per line; it adds no abilities of its own and opens no network connection. The tool's name must not be `siivos`: on a Mac's disk that is the same file name as `SiivOS`.
- No third-party dependencies and no network calls unless the owner approves them (privacy-first principle). The one approved exception is ClamAV: SiivOS runs a ClamAV the user installed themselves and bundles none of it, and its updater downloads virus definitions only when the user clicks the button for that.
- Nothing destructive without an explanation shown first and an undo path. Removed items go to a restorable holding area.

## Text and languages

- The app is in English and Finnish. Every text shown to people is written as `tr("English text")`, in the engine and in the screens alike. Changing parts are marked `%1$@`, `%2$@` and passed as extra arguments; never put `\(...)` inside `tr`.
- The Finnish wording lives in `Sources/SiivOSCore/Localization/FinnishTexts.swift`, one pair per line. Add the Finnish for every new text in the same change. `Scripts/check-translations.py` (run by the Linux check) fails if any is missing.
- Finnish terms in use, chosen by the owner where marked: app = sovellus (owner; not "appi"), health = terveys (owner; not "kunto"), Health Timeline = Terveystiedot (owner), holding area = välivarasto, cache = välimuisti, item = kohde, Cleanup = Siivous, History = Historia, processor = suoritin, Activity Monitor = Järjestelmän valvonta, background item = taustakohde, browser extension = selainlaajennus, configuration profile = määritysprofiili, Full Disk Access = täysi levyn käyttöoikeus, virus definitions = tunnistetiedot, Terminal = Pääte. The one exception is "Appien hallinta", which names a page in macOS's own System Settings.
